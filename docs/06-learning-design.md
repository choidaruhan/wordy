> M6 구현 계약은 [07-learning-engine.md](07-learning-engine.md)를 따른다.
> 07과 이 문서가 충돌하면 M6 범위에서는 07이 우선한다.

## 0. 전제: 암기란 무엇인가

인지심리학에서 100년 넘게 반복 검증된 사실 두 개만 가져옵니다.

> **① 인출 연습(testing effect)**
> 다시 읽는 것보다 **기억에서 꺼내보는 것**이 압도적으로 오래 남는다.
> (Roediger & Karpicke, 2006)
>
> **② 간격 효과(spacing effect)**
> 같은 총 시간이라면 몰아서보다 **나눠서**가 오래 남는다.
> (Ebbinghaus, 1885 — 아직도 유효)

이 둘을 합치면 앱의 정체성이 정해집니다.

> **이 앱은 "단어장 뷰어"가 아니라 "인출 훈련기"다.**
> 사용자가 답을 꺼내려고 애쓰는 순간이 학습이 일어나는 순간이고,
> 앱의 임무는 그 순간을 **적당히 어렵게, 적당한 간격으로** 반복해서 만들어주는 것이다.

따라서 다음은 **금지**입니다.

| 금지 | 이유 |
|---|---|
| 단어 목록을 훑어보게 하기 | 인출이 일어나지 않는다. "읽었다"는 착각만 남는다 |
| 뜻을 항상 같이 보여주기 | 꺼낼 필요가 없어진다 |
| 정답을 0.5초 만에 공개 | 애쓰는 시간이 곧 학습량이다 |
| 하루에 200개 몰아주기 | 간격 효과가 사라진다 |

## 1. 카드 1장의 5단계

모든 화면은 이 루프의 변형입니다.

```
① 자극(cue) 제시
      │   예: "ubiquitous"
      ▼
② 인출 시도  ←── 여기가 학습. 앱은 여기서 아무것도 안 함
      │   사용자가 머릿속으로(또는 타이핑으로) 답을 만든다
      ▼
③ 피드백 공개
      │   뜻 + 품사 + 예문 + 발음
      ▼
④ 자기평가 or 자동채점
      │   모름 / 늦게 떠오름 / 바로 떠오름 (아주 쉬움)
      ▼
⑤ FSRS가 다음 등장 시점 계산
```

**핵심은 ②에 시간을 주는 것.** 자극이 뜨자마자 답이 보이면 그 카드는 학습 가치가 0입니다.

> 자기평가 화면은 **“답을 보기 전에 뜻이 떠올랐나요?”**를 먼저 묻는다.
> 답을 본 뒤의 느낌이 아니라, 보기 전에 떠올린 기준으로 고르게 해야 한다.

### 구현 규칙

- 정답 공개는 **반드시 사용자 액션**으로 (`Space` / 카드 탭). 자동 타이머 공개 없음.
- 카드 1장 목표 소요: 뒤집기형 **6~10초**, 타이핑형 **15~20초**.
- ②에서 30초 이상 막히면 "모르겠어요" 버튼 → 바로 공개 + `Again`. 좌절 방지.

## 2. 카드 유형 4종

단어 하나(`words` row)가 **여러 장의 카드**를 만듭니다. 카드마다 FSRS 상태가 독립입니다.

| 유형 | 자극 | 사용자가 하는 일 | 난이도 | 도입 |
|---|---|---|---|---|
| `recognition` | `ubiquitous` | 뜻을 떠올린다 | ★ | **M2** |
| `recall` | `어디에나 있는` | **철자를 입력한다** | ★★★ | **M3** |
| `cloze` | `Smartphones are ___ these days.` | 빈칸에 단어를 넣는다 | ★★ | M3.5 |
| `listening` | 🔊 (음성) | 듣고 철자를 입력한다 | ★★★ | M6.5 (기본 꺼짐) |

### 왜 `recognition`만으로는 부족한가

`recognition`(영→한)은 **재인**입니다. 보면 안다. 하지만:

- 시험에서 답을 쓸 때 필요한 건 **재생(recall)** 이다.
- 재인은 **자기평가에 의존**한다. "뜻이 생각난 것 같다"와 "생각났다"를 구분 못 한다.

`recall`(한→영)은 **철자를 입력해야 하므로 객관적으로 채점**됩니다.
그래서 이 앱은 **학습이 진행될수록 무게중심을 `recall`로 옮깁니다.**

> **설계 주장**: 영→한 카드는 "입구"이고, 한→영 카드가 "출구"다.
> 입구만 있는 단어 앱(대부분의 경쟁 앱)은 사용자가 시험장에서 쓸 수 있는 상태까지 데려가지 못한다.

### 승급(grading up) 규칙

`recall` 카드는 처음부터 만들지 않습니다. 복습 부담이 2~3배가 되니까요.

```
recognition 카드가  state = 'review'  AND  scheduled_days >= 4
        └─→ recall 카드 생성 (due = now)

cloze 카드는  words.example IS NOT NULL
         AND  recognition 카드 stability >= 7
        └─→ cloze 카드 생성
```

승급은 평점 저장과 **같은 트랜잭션**에서 확인합니다 (`maybeUnlockCards()`).
사용자는 "이 단어 이제 쓸 수 있는지 물어보네"라고 느끼고, 실제로 그게 맞습니다.

### 예상 복습 부하

| 단어 수 | recognition | recall | cloze | 하루 복습(안정화 후) |
|---|---|---|---|---|
| 300 | 300 | 300 | ~200 | 60~90 |

→ **`daily_new` 기본값은 10.** 20으로 시작하면 2주 뒤 무너집니다.
→ 온보딩에서 "하루 5분 / 10분 / 20분" 중 고르게 하고 `daily_new`를 5/10/20으로 매핑.

## 3. 신규 단어는 "시험"이 아니라 "소개"로 시작

처음 보는 단어를 곧바로 시험내면 아무것도 배우지 못합니다.
(`recognition` 카드도 첫 1회는 예외입니다.)

```
신규 카드 첫 등장:
   ┌──────────────────────────┐
   │  ubiquitous              │
   │  /juːˈbɪkwɪtəs/    🔊     │
   │  어디에나 있는            │
   │  Smartphones are         │
   │  ubiquitous these days.  │
   │                          │
   │      [ 알겠어요 ]         │
   └──────────────────────────┘
        ↓ 3~5초 노출 후
   ┌──────────────────────────┐
   │  이제 뜻이 가려집니다      │
   │  ubiquitous              │
   │      [ 뜻 보기 ]          │
   └──────────────────────────┘
```

- 첫 노출은 **뜻을 보여주고**, 같은 세션 안에서 곧바로 가려서 한 번 더 묻습니다.
- 이 "제시 → 즉시 인출"이 신규 단어 기억률을 크게 올립니다.
- 구현: `cards.reps = 0` 이면 소개 모드로 렌더. 별도 테이블 불필요.

## 4. 하루 세션 구조 (10분 기준)

```
[1] 워밍업          2분   어제 Again 받은 카드 3~5개
[2] 복습            4분   FSRS 큐 (영→한 · 한→영 · 빈칸 혼합)
[3] 승급            1분   새로 승급된 한→영 / 빈칸 카드
[4] 신규 소개       2분   새 단어 8~10개 (제시 → 즉시 인출)
[5] 마무리          1분   오늘 세션에서 Again 받은 카드 재시험
```

### 왜 5단계가 필요한가

| 단계 | 근거 |
|---|---|
| 워밍업 | 세션 초반 이탈 방지. 쉬운 성공을 먼저 맛보게 한다 |
| 복습 | 간격 효과의 본체. 어려운 복습을 회피하지 않도록 먼저 둔다 |
| 승급 | 생산 연습을 복습 직후에 붙인다. 신규보다 먼저 둔다 |
| 신규 소개 | 신규를 복습 사이에 섞으면 인지 부하가 급증한다. 따로 묶는다 |
| 마무리 재시험 | 틀린 것을 **세션 안에서** 한 번 더 꺼내면 그날 기억이 크게 개선된다 |

> **금지**: 신규와 복습을 무작위로 섞는 것. Anki의 기본 동작이지만 초보자에게는
> "모르는 것 + 헷갈리는 것"이 뒤섞여 좌절감이 커집니다. 단계를 나누세요.

> M6.3부터 이 구성을 `daily_plans`에 하루 스냅샷으로 고정한다.
> 복습이 밀리면 신규 수를 자동으로 줄이고, 이유를 화면에 표시한다.
> 복습 블록은 영→한 50% · 한→영 30% · 빈칸 20%로 섞는다.
> 자세한 계산은 [07-learning-engine.md](07-learning-engine.md) 5~6절.

### 단어장 필터

기본은 **전체 단어장 통합**으로 냅니다(간섭 학습 효과). 단, 사용자가 특정 단어장만 고를 수 있게 필터를 제공합니다.

## 5. 철자 채점 규칙 (`recall` / `cloze`)

입력값을 그대로 채점하면 오타에 지나치게 엄격해집니다. 실제로는 정답을 알고 있었기 때문입니다.

```ts
function grade(input: string, answer: string): { ok: boolean; typo: boolean } {
  const norm = (s: string) => s.toLowerCase().trim().replace(/\s+/g, ' ');
  const a = norm(input), b = norm(answer);

  if (a === b) return { ok: true, typo: false };

  // 정답이 여러 개면 "/" 구분: "ubiquitous / omnipresent"
  const candidates = answer.split('/').map(norm);
  if (candidates.includes(a)) return { ok: true, typo: false };

  // 오타 허용: 긴 단어일수록 관대하게
  const best = Math.min(...candidates.map(c => levenshtein(a, c)));
  const allowed = b.length >= 8 ? 2 : b.length >= 5 ? 1 : 0;
  if (best <= allowed) return { ok: true, typo: true };

  return { ok: false, typo: false };
}
```

| 결과 | 평점 | 처리 |
|---|---|---|
| 정확 | `Good` (3) | 보통 |
| 오타 인정 | `Good` (3) | "철자 주의: ubiquit**a**s" 표시, 단어에 `spelling_warn` 플래그 |
| 오답 | `Again` (1) | 정답 공개 후 재학습 |

- **정답 공개 시 철자 차이를 하이라이트**합니다 (맞은 글자/틀린 글자).
- 오타는 3회 누적되면 카드에 철자 집중 표시.

> 이 채점이 이 앱에서 유일하게 "객관적인" 학습 측정입니다. 여기에 투자할 가치가 있습니다.

## 6. 막힌 단어 처리 (leech)

`lapses >= 8` 인 카드는 자동으로 **"격리된 단어"** 목록으로 이동합니다.

- 큐에서 제외 (`suspended = 1`)
- 별도 화면에서 사용자가 직접 **연상법(mnemonic)** 을 적게 유도:
  ```
  vulnerable  →  "벌너러블... 벌(벌레)이 붙을 만큼 약한 상태"
  ```
- **자기 생성 효과(generation effect)**: 스스로 만든 연상은 남이 준 것보다 잘 남습니다.
- 연상법은 해당 단어의 모든 카드 복습 화면에 함께 표시됩니다.

> 이게 없으면 사용자는 같은 단어를 하루에 8번 틀리면서 앱을 떠납니다.
> "이 단어는 잠시 내려놓으세요"라고 말해주는 것이 기능입니다.

### weak와 leech는 다르다

M6부터 둘을 분리합니다.

| 구분 | weak | leech |
|---|---|---|
| 정의 | 최근 성과가 나쁜 단어 (최근 20회 + lapses + stability + 퀴즈) | `lapses >= 8`로 큐에서 격리된 카드 |
| 상태 | 저장하지 않음 (읽을 때 계산) | `cards.suspended = 1` |
| 연습 | 기한이 도래한 카드만 `/review?mode=weak` | 연상법 작성 후 `resume` |
| 스케줄 | 기존 FSRS 그대로 | 복귀 전까지 큐 제외 |

weak는 “지금 약한 단어”, leech는 “잠시 내려놓은 단어”입니다. leech를 weak 연습에 넣지 않습니다.
정확한 점수식은 [07-learning-engine.md](07-learning-engine.md) 4절.

## 7. "외웠다"를 어떻게 정의할 것인가

사용자가 가장 알고 싶어하는 것: **"나는 몇 개 외웠나?"**

단순히 "카드 300개"는 의미 없습니다. 한 번 본 것도 포함되니까요.

> **정의 (M6부터 단어 단위)**
> - **Known**: 영→한 카드 `scheduled_days >= 21` + 생산형 카드(한→영/빈칸) 중 하나가 `>= 7`
> - **Mastered**: 영→한 `>= 60` + 존재하는 모든 생산형 카드 `>= 21`
> - 생산형 카드가 하나도 없으면 Known/Mastered가 아니다.

카드 수가 아니라 **고유 단어 수**로 센다. 영→한·한→영·빈칸이 각각 21일을 넘겨도 단어는 1개다.
정확한 판정식과 예외는 [07-learning-engine.md](07-learning-engine.md) 2.3이 기준이다.

### 대시보드

```
외운 단어 (Known)
  128  /  400        ← 영→한 21일 + 생산형 카드 7일
  ████████░░░░░░░  32%

마스터 (Mastered)  42
학습 중  184
새 단어   88
어려운   12
```

### 왜 이게 중요한가

- Anki에는 없는 지표입니다. Anki는 "due 카드 수"만 보여줘서 **성취감이 안 생깁니다.**
- `scheduled_days`로 자동 계산되므로 별도 상태 저장이 필요 없습니다.
- 이 숫자가 늘어나는 것이 이 앱의 유일한 게임화 장치입니다. (뱃지·포인트 없음)
- “뜻은 아는데 못 쓴다”를 막기 위해, 출구 카드가 없으면 외운 단어로 세지 않는다.

## 8. 동기부여 장치 (최소한만)

과도한 게임화는 학습을 방해합니다. 3개만 씁니다.

| 장치 | 구현 | 이유 |
|---|---|---|
| **연속 학습일 (streak)** | `reviews.local_date` 연속 카운트 | 가장 강력하고 가장 단순 |
| **외운 단어 수** | 위 정의 | 실질적 성취 |
| **오늘의 진행률** | `7 / 20` | 세션 완료감 |

**넣지 않는 것**: 포인트, 리더보드, 뱃지, 친구 초대, 푸시 알림 스팸.
개인 학습 앱에서 이런 건 초반엔 재밌고 2주 뒤엔 짜증이 됩니다.

## 9. 무엇을 외울 것인가 (콜드 스타트)

"어떻게"만큼 중요한 게 "무엇을". 단어를 직접 입력하게 하면 대부분 여기서 이탈합니다.

### v1 전략

| 순서 | 방법 |
|---|---|
| 1 | **기본 단어장 3종 제공** (빈도 기반, 공개 라이선스): `수능 기본 1,000` / `토익 800` / `회화 빈출 500` |
| 2 | CSV 임포트 |
| 3 | 직접 입력 (마지막) |

- 기본 단어장은 `public/seeds/basic-1000.csv` 로 넣고, 사용자가 "추가"하면 자기 `decks` 로 복사.
- 포맷·검수 방법은 [03-data-model.md](03-data-model.md) 의 "CSV 형식" 참고.
- 현재 **1,000개 완료**. 기능어(the, of, and…)는 제외하고 학습 가치가 있는 어휘만 담았습니다.
- 온보딩: 목표 선택 → 단어장 1개 선택 → **10개 즉시 체험** → 가입.
  (가입을 마지막에 두면 이탈이 줄어듭니다. 단, 세션 저장을 위해 결국 필요)

### 예문이 없는 단어

예문 유무가 기억률에 큰 차이를 만듭니다(맥락 부호화).

- 예문 없는 단어는 `recognition` 카드만 생성 (cloze 승급 불가)
- 단어장 화면에 **"예문 없는 단어 43개"** 를 눈에 띄게 표시 → 사용자가 채우게 유도
- AI 예문 생성은 v1.2 (비용·정확도 문제로 MVP 제외)

## 10. 화면별 학습 요소 요약

| 대시보드 | 외운 단어 수로 성취 부여, 오늘 할 양 예고 |
| 세션 | 인출 → 피드백 → 평가 (본체) |
| 단어장 | 예문·발음 보강 = 맥락 추가 (수동 학습) |

| 통계 | 어떤 단어장이 약한지 파악 |

## 12. 검증 방법

만들고 나서 "잘 외워지나?"를 확인할 지표:

| 지표 | 의미 | 목표 |
|---|---|---|
| 하루 세션 완료율 | 큐를 다 돌았는가 | 80% |
| `recognition` 정답률 | 너무 쉽/어려운가 | 85~90% (`rating >= 2` 기준) |
| `recall` 오답률 | 진짜 약점이 드러나는가 | 20~30% (너무 낮으면 승급이 이름) |
| 21일 이상 유지 카드 비율 | 예약 기준 장기 기억 전환율 | 30일 후 40% |
| `retention_21d` | 실제 21일 후 회상 성공률 | 40% 이상 |
| `Again` 연속 3회 카드 수 | 좌절 구간 | 전체의 5% 이하 |
